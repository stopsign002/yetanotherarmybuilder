# Batch 2026-10-25 — sessions that stay signed in, a real signed-out state, destroyed units sink in Play

Contract for three independent items. Workers build exactly this; the session
reviews each diff against it, runs the checks, does the browser pass, writes
the changelog entries, stamps, commits and pushes. **Workers do not commit, do
not touch `js/data/changelog-data.js`, `index.html` (except where an item says
so) or `sw.js`.**

Why (facts from the access logs and `sessions` table, 2026-10-25): the session
cookie is a hard 30 days from login and is never renewed, so every device
signs out on day 30 regardless of use; the owner's phone runs Brave AND Chrome
with their own cookies; and a signed-out page load flips to anonymous with no
visible cue (the topbar reads "Account" on desktop and is hidden on phones),
so one browser ran signed out for 12 days with every edit landing in
localStorage only.

## Item A — sliding one-year sessions (owner: worker A, repo `../api`)

Files owned: `api/sessions.js`, `api/server.js`, `api/CLAUDE.md`. Nothing else.

Contract:
- `SESSION_TTL_MS` becomes **365 days**. Add `SESSION_RENEW_AFTER_MS = 24h`.
- In the `preHandler` in `server.js` (give it the `reply` argument), after a
  session loads for a non-revoked user: if `expires_at - now() <
  SESSION_TTL_MS - SESSION_RENEW_AFTER_MS` (i.e. the row was last extended more
  than a day ago), call a new `touchSession(sid)` in `sessions.js` that runs
  `UPDATE sessions SET expires_at = now() + interval '365 days' WHERE
  session_id = $1` and then `reply.setCookie(COOKIE_NAME, sid, cookieOpts())`
  so the browser's `Max-Age` moves with it. Skip the touch when
  `req.url` starts with `/auth/logout`. A touch failure must not fail the
  request (`try/catch`, `req.log.warn`).
- Existing 30-day rows are extended to a year on their next request — that is
  the point; no migration.
- Prune: `pruneSessions()` in `sessions.js` = `DELETE FROM sessions WHERE
  expires_at < now()`. Call it once after `migrate()` in `server.js` and every
  24 h via `setInterval(...).unref()`. Log the row count at `info`.
- `api/CLAUDE.md`: update the "Auth + sessions" section (TTL, sliding renewal
  rule, prune) and the one-line summary at the top that says "30-day".
- Self-check: `node --check` on both files, then `docker compose -f
  ~/sites/sites/yetanotherarmybuilder/docker-compose.yml up -d --build` and
  `curl -s https://yaab.thewheeliebois.com/api/healthz` → `{"ok":true}`, and
  `docker logs --since 2m yaab-api` shows the prune line and no error. Do NOT
  log in as anyone; the session verifies the renewal with a fixture account.

## Item B — a real signed-out state (owner: worker B, repo `app`)

`js/ui/auth-button.js`'s tag). `docs/MODULE-REFERENCE.md` gets an entry for

Contract:
1. **`auth.js` reports why a session ended.** `notify()` takes an optional
   `meta` and passes it as the second argument to every listener
   (`listener(user, meta)`); existing listeners ignore it. `setUser(user,
   meta)` forwards it. Call sites: `init()`'s 401 branch →
   `setUser(null, { reason: 'expired' })` **only if `primeFromHint()` had
   returned a user** (an anonymous visitor gets no notification, as today);
   `handleSessionExpired()` → `{ reason: 'expired' }`; `logout()` →
   `{ reason: 'logout' }`. Everything else unchanged.
2. **Topbar button says what it is.** In `auth-button.js`, the signed-out
   label is **"Sign in"** (not "Account"), title "Sign in to sync your
   armies". `css/auth.css` styles `.auth-btn-signed-out` with a 1px
   `var(--accent)` border and `rgba(var(--accent-rgb), 0.10)` background so it
   reads as a call to action next to the plain action buttons; signed-in is
   unchanged. Check it in all three themes (`localStorage.yaab_theme` =
   `grimdark` | `brutalist` | `brutalist-dark`) — brutalist overrides
   `.topbar-action-btn` at `css/themes/brutalist.css:361`, so use tokens and
   verify the border is visible on the cream ground, do not hardcode colours.
3. **Banner on an expired session.** `signed-out-banner.js` (IIFE, `App.hooks`
   guard, registers on `App.hooks.bootstrap`) subscribes to
   `App.Auth.onChange((user, meta) => …)`. When `user` is null and
   `meta && meta.reason === 'expired'`, it mounts (once) a full-width strip
   `#signed-out-banner` as the first child of `<body>` after `#topbar`
   (so it sits under the topbar on desktop and at the very top on phones):
   text **"You're signed out in this browser — your changes stay on this
   device until you sign in."**, a **Sign in** button (opens
   `UI.showAuthModal('login')`) and a **×** dismiss button (`aria-label="Hide"`).
   Both are real buttons with the house button styling (border, padding,
   hover) — never a bare link. On any `onChange` with a non-null user the
   banner is removed. Dismiss writes `sessionStorage.yaab_signed_out_banner =
   '1'`; while that is set the banner is not shown again in this tab (a new
   tab or app launch shows it again — that is intended). Storage key
   documented in the module header.
   On phones also set the More tab dot: `document.querySelector('.mobile-tabbar
   [data-badge="more"]').textContent = '•'` while the banner condition holds,
   and clear it when a user signs in (the bar is injected on bootstrap by
   `js/app/pwa-install.js`; query it lazily, it may not exist yet).
   Styles in `css/auth.css`, tokens only; the strip uses
   `var(--panel-bg)` ground, `var(--accent)` top border, body text
   `var(--text)`. Must not overlap `.mobile-tabbar` or the sticky points pill.
4. Self-check: `node --check` on each JS file; `browse.sh shot
   https://yaab.thewheeliebois.com /tmp/b-shot` and confirm the topbar reads
   "Sign in" on desktop; then a `browse.sh run` script that sets
   `localStorage.yaab_auth_session_hint = '{"username":"ghost"}'` before load
   and asserts `#signed-out-banner` appears at 1440 and 390, the × hides it,
   and a reload in the same context does not show it again. No login.
