# CSS reorganisation — 2026-10-31 (contract)

The simplification pass (`docs/SIMPLIFY-2026-10-31.md`) folded most of the
patch stylesheets but left 131 rules in `card-chassis.css`, `aaa-polish.css`
and `detail-redesign.css` because moving them would have reordered an
equal-specificity competitor. This pass stops folding and **reorganises the
stylesheets by component, with the load order declared**, proving by data
rather than inspection that every element computes the same style as before.

Branch `css-reorg`, worktree `~/sites/sites/yetanotherarmybuilder/css-work`.
The live app (`~/sites/sites/yetanotherarmybuilder/app`) is served from disk
and is **not** touched until the session merges.

## Non-goals (a change here is a defect)

- No visual change, in any theme, at any width, in any state. The three
  proofs in §4 are the acceptance test.
- No selector renames, no class/id changes, no DOM or JS changes. JS files
  are not owned by anyone in this pass.
- `css/themes/brutalist.css` is **not touched**. It is appended last by
  `js/theme-boot.js`, so it wins every equal-specificity tie regardless of
  how the files below it are arranged.
- No `@layer`. The order is declared by the `<link>` sequence and the tier
  comment in `index.html`; introducing cascade layers changes the semantics
  of specificity and would make the proof below invalid.
- No specificity bumps (`.a.a`) to dodge an order conflict. If two rules
  must keep their order, they live in the same file in that order.
- No behaviour "improvements" while passing through. Note the temptation
  in the report.

That comment is the point of the exercise — the dependency becomes visible
next to the rule instead of hidden in the link list.

Where a rule's selector could plausibly live in two files (a `.detail-*`
rule inside `#play-mode`, say), it goes with the **owner of its subject
compound** (the last compound selector), and the mode file keeps only rules
whose subject is the mode's own class.

## 2. The order-preservation rule (what "same cascade" means)

Flatten old and new stylesheet sets to declarations in document order (the
`<link>` order, then source order; `@media`/`@supports` bodies inline where
they appear — a conditional rule and an unconditional one can both apply, so
conditions never make two declarations independent).

For every pair of declarations **D1 before D2** in the old order with

- the same property,
- the same `!important` flag,
- equal specificity (`css-tool.py specificity()`, or an equivalent),
- selectors that **can co-match** (§3),

D1 must still precede D2 in the new order. Nothing else about order matters
to the cascade. Declarations may move freely across files otherwise; rules
with identical selector+media may be merged when every constraint still
holds; declarations that lose to a later same-selector same-media
declaration of the same property and importance are dead and may be deleted.

`scripts/verify/css-order-check.py <old-tree> <new-tree> [matches.json]`
(W-B writes it; it stays in the repo as a safety net for future CSS edits)
prints every violated pair as `old(file:line sel{prop}) must precede
old(file:line sel{prop}) — new order: file:line, file:line` and exits 1 if
any. Without `matches.json` it assumes every pair can co-match
(conservative). It also lists selectors present in old and absent in new
(every one must be either merged or proven dead) and any `@keyframes`,
`@font-face` or `:root` token that disappeared.

## 3. Co-match evidence (the capture)

`scripts/verify/css-cascade.mjs` (W-A) drives the live app through the
states below in 3 themes × 2 widths and writes, per state, every element's
computed style, and once per run a **match map**: for each selector in the
loaded stylesheets (split on top-level commas, state pseudo-classes
`:hover :focus :focus-visible :focus-within :active :visited :target
:placeholder-shown` and all pseudo-elements stripped), the set of elements it
matched in any state. Two selectors can co-match iff their sets intersect;
a selector that could not be evaluated after stripping is `null` and is
treated as co-matching everything.

Run via `~/sites/base/browser/browse.sh run scripts/verify/css-cascade.mjs <outdir>`.
Env (forward with `BROWSE_ENV`):

- `CSS_FROM=/out/candidate` — when set, `index.html` and every `css/*`
  request is fulfilled from that directory (which the session copies into
  the outdir before the run) instead of the live server. This is how the
  candidate is measured without touching live.
- `THEMES` (default `grimdark,brutalist,brutalist-dark`), `WIDTHS`
  (default `1440,390`), `STATES` (default all).

States (id — how to reach it; all start from a booted page):

| id | state |
|---|---|
| `01-empty` | boot, no faction |
| `02-build` | Death Guard selected, Plague Marines and Typhus added via the detail Add button, Typhus detail open, search cleared (exactly `scratchpad/simplify/snap.mjs`) |
| `02h-card-hover` | 02 + pointer hovering an **unselected** unit card |
| `02s-selected-hover` | 02 + pointer hovering the **selected** (Typhus) card |
| `02f-focus` | 02 + search input focused by click, then one `Tab` (so one control has `:focus-visible`) |
| `02x-export-menu` | 02 + the Export dropdown open (`.dropdown-trigger[title="Export this army"]`) |
| `02t-tools-menu` | 02 + the Tools dropdown open |
| `02a-army-hover` | 02 + pointer hovering an army-list entry |
| `03-army-phone` | phone only: army tab |
| `04-cards` `05-play` `06-waha` `07-collect` | `App.setMode(m)` |
| `08-drawer` | build mode + settings drawer open |
| `09-palette` | command palette open (find the key or `App` entry point in `js/`) |
| `10-changelog` | changelog modal open (`#yaab-btn-changelog`) |
| `11-glossary` | a glossary keyword popover open in the detail pane (`#glossary-pop`), if reachable by click |

A state that cannot be reached is **reported, not skipped silently**.

Output, per `<theme>-<width>-<state>.json.gz`: `{ state, theme, width,
elements: [{ path, tag, id, classes, pseudo: null|'::before'|'::after',
styles: [pairId...] }], pairs: ["prop:value", ...] }` — `path` is a
root-to-element nth-child path, stable while the DOM is unchanged; every
element in the document is included, plus `::before`/`::after` when their
`content` is not `none`; `styles` lists **every** computed property as an
index into the interned `pairs` table. `matches.json.gz`: `{ elements:
[path...], selectors: { "<selector>": [elementIndex...] | null } }`.
Target: a full capture set under 25 MB.

`scripts/verify/css-cascade-diff.mjs <beforeDir> <afterDir>` (node only, no
browser): for every state present in both, report missing/extra elements
and, per element, each property whose value differs, as `state  path
(tag#id.classes)  prop: before → after`; collapse identical diffs that
repeat across elements (`×N`); exit 1 on any difference; print `N states,
M elements, 0 differences` when clean.
