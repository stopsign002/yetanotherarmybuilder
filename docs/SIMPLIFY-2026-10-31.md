## Rules for every worker

- **No behaviour change.** Same DOM, same classes, same storage keys, same
  API shapes, same renderer contract (`docs/PARSER.md`, `docs/DATASET.md`).
  Reference screenshots of 8 states × 3 themes × 2 widths were taken before
  you started; the session pixel-diffs them after. A visible change is a
  defect unless this document lists it as intended.
- **Edit only your owned files.** If a dedupe needs a change in a file you do
  not own, write the helper in your file and list the call sites to switch in
  your report; the session or that file's owner switches them.
- No git, no changelog, no stamps, no browser suites as sign-off, no live DB.
  Cheap checks: `docker run --rm -v "$PWD":/w -w /w node:22-slim node --check <file>`
  for every file you touched, `grep` proofs that a removed symbol has no
  remaining references, and for CSS a brace-balance + "every deleted selector
  has zero matches in js/ and index.html" check.
- Keep the app buildless: IIFEs, `window.App`/`window.UI`, no imports in app
  code. Shared helpers live on `window.UI` (DOM/formatting) or `window.App`
  (state/storage) in the files named below; call sites use them directly.
- Do not "improve" behaviour while you are there. Log the temptation in the
  report instead.
- Report (≤250 words): files touched with line delta each (`wc -l` before →
  after), helpers created and how many call sites switched to each, symbols
  removed with the grep proof, anything you wanted to change but did not.
